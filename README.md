# 又见-微信转发工具（功能说明）

> 本仓库**只包含功能说明文档**，不包含任何源代码、安装包或可执行文件。
> 这是一份「这个工具能做什么、怎么配置、边界在哪」的说明书，方便有同类需求的人理解思路。

---

## 一、这是什么

一个跑在 Windows 上的**微信群消息监听 + 自动转发**工具。

典型场景：你在某个群里需要盯着消息，一旦有符合条件的消息就要转到另一个群或某个联系人，
但手动盯群太累、容易漏。这个工具可以替你盯着，按你定的规则自动转发。

设计上有一条**不可妥协的红线**：

> **只操作「小号」（工作号），绝不碰「大号」（个人号）。**
> 同时登录两个微信时，工具必须按账号数据库精确锁定属于小号的那个窗口；
> 一旦无法确认，就停下来提示人工确认，而不是随便挑一个窗口操作。

---

## 二、核心功能

| 功能 | 说明 |
| --- | --- |
| **消息监听** | 持续监听指定群 / 联系人的新消息 |
| **规则转发** | 按「关键字 → 目标」的规则决定这条消息转到哪里；也可以配置成全部转发 |
| **多目标转发** | 一条消息可以同时转发给多个群 / 联系人 |
| **文本替换** | 转发时自动把内容里的某些文字换成别的（例如统一口径、去除来源标识） |
| **@群成员** | 转发到群时，可以按群昵称 @ 指定成员 |
| **发言人识别** | 转发内容里带上「谁说的」：优先显示该成员在这个群里的**群昵称**，没有则回退个人昵称，实在识别不出就显示「群成员」 |
| **时间戳** | 带消息的精确发送时间 |
| **多规则配置** | 用一个纯文本配置文件描述「监控谁 → 转发到哪 → 怎么替换 → @谁」 |

---

## 三、配置文件长什么样

配置是一个 UTF-8 的纯文本文件，由若干「配置块」组成，块与块之间用空行隔开：

```
监控对象:要监听的群名或联系人名
识取并转发:转发目标
替换:旧内容->新内容,旧内容2->新内容2
群成员昵称:要@的昵称
```

说明：

- 后两行（`替换`、`群成员昵称`）是可选的，不需要就整行不写。
- `识取并转发` 支持两种写法：
  - **全部转发**：`识取并转发:目标A$&¥目标B`
    （多个目标之间用 `$&¥` 分隔）
  - **按关键字转发**：`识取并转发:关键字1->目标A$&¥目标B,关键字2->目标C`
    （关键字之间用 `$&¥` 分隔，不同规则之间用逗号分隔）
- 冒号和逗号全角半角都认，程序会自动转换。
- **但 `监控对象:` 和 `识取并转发:` 这两个前缀必须原样保留**，行首必须是它们，
  不能简写成 `群名:目标`。少写前缀是新手最常踩的坑，会直接报「配置文件中没有有效的配置」。

## 四、怎么用

1. **先把小号打开并登录好在桌面上**，确认能正常点开窗口。
2. 准备好配置文件（按上面第三节写），保存成 UTF-8 编码。
3. 启动工具，在界面里**选择配置文件**，点**开始**。
4. 状态栏会显示运行进度；点**停止**可以随时结束。
5. 日志会写到本地文件，出问题可以翻日志。

### 两个使用注意（都是实测踩出来的）

- **不要在小号「已关闭但后台还在」的状态下启动工具**。
  小号最小化到任务栏没问题，但如果窗口被隐藏了，程序自动去「召回」它时，
  可能出现「窗口显示出来了、但微信内部控件还没就绪」的尴尬状态 —— 这时人和程序都点不动它。
  正确做法：启动工具前，先手动点开小号窗口，确认能正常操作。
- **同时登录两个微信时，工具只认小号**。如果它提示无法确认窗口归属，
  不要强行继续，先人工确认哪个窗口是小号。

## 五、实现思路（不含代码）

监听消息有两条技术路线，工具都做过验证：

| 路线 | 原理 | 优缺点 |
| --- | --- | --- |
| **UI 自动化** | 用 Windows UI Automation 读取微信窗口里的消息列表控件 | 不依赖数据库，但依赖界面结构；微信改版可能失效 |
| **本地数据库** | 直接只读微信本地的 SQLCipher 数据库，按消息序号增量读取 | 不依赖界面结构、更稳定、能拿到精确时间；需要先取到数据库密钥 |

工程上比较有价值的几个点：

1. **保活**：UI Automation 的 COM 对象容易失效，需要一个轻量保活线程定期访问窗口（约 0.8 秒一次）维持连接。
2. **防发错人**：发送前先校验「当前聊天窗口是不是目标」，不是就切换过去，切换后再校验一次；
   发送失败重试若干次。宁可失败，也不能发错人。
3. **不吞首条消息**：增量监听要正确处理起始序号，否则启动后的第一条消息会被跳过。
4. **故障显性化**：监听器启不起来时必须报错并写日志，
   不能「静默跳过」——那样用户会以为在正常工作，其实一条都没转。
5. **发言人与群昵称**：微信 4.x 的群昵称不直接存在联系人表里，
   需要额外解析联系人数据库里的二进制扩展字段才能取到。

> 说明：微信版本更新可能改变界面结构或数据库格式，
> 上述方案在特定版本上验证过，换版本需要重新确认。

## 六、局限与风险（请先读）

**技术局限**

- 微信客户端更新后，UI 自动化方案可能失效，需要重新适配。
- 部分消息拿不到发送者信息，只能显示「群成员」。
- 本地数据库方案需要读取进程内存以获得解密密钥，属于较敏感的操作。

**使用风险**

- 微信官方对自动化操作的态度是明确的。使用第三方工具操作微信客户端，
  **存在账号被限制甚至封禁的风险**，请自行评估。
- 在群里自动转发内容，涉及他人看到的信息，请确保你有权这么做。
- 转发内容可能涉及个人隐私，请遵守相关法律法规。
